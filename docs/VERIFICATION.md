# 验证记录

2026-10-26，1.2.0 独立构建在 Windows 11 / 150% 缩放 / Windows PowerShell 5.1 / PSReadLine 2.0 / Python 3.13 上验证。

## 1.2.0 原生菜单与 DPI

- 改造前只读测得：AKKO 为 System Aware，SoundKeeper 和 SteamMonitorTray 为 DPI Unaware；SoundKeeper 的 pystray Windows 后端已经使用原生菜单。两个参考项目未修改。
- 新 UI 构建显式面向 .NET Framework 4.8，启用 Common Controls v6 和 Per-Monitor V2。正式程序和测试程序使用相同清单、运行配置与 UI 程序集。
- 在实际窗口上验证 Per-Monitor V2 上下文（不仅检查配置文本），当前菜单宿主 DPI 为 144；宿主保持隐藏。
- 通过原生 API 检查子菜单、Unicode、字面量 &、勾选、禁用及取消命令；循环创建/销毁 200 份菜单树，USER 资源未持续增长。
- UI Automation 只操作本地测试进程的原生菜单：验证真实选择返回后菜单句柄已释放，命令仅执行一次。
- FakeMonitor 最小化后打开真实原生主菜单和配置子菜单，后台状态变化期间菜单保持展开；下一份快照读取新状态。通过实际子菜单的“停止监测”完成真实 Ctrl+C 清理。
- 六种语言的设置窗口实际创建于 150% DPI，检查说明文本和按钮尺寸，并用虚构路径保存布局预览；修复法语保存按钮裁切，保存/取消改为按文字自动调整宽度。
- 构建支持独立输出目录，打包使用独立暂存构建；新便携包包含必须与 EXE 配套的 SteamMonitorTray.exe.config，白名单增加至 11 个运行文件。
- Windows PowerShell 5.1 下完成独立构建和 1.2.0 打包，源文件/暂存区/历史及实际 ZIP 扫描通过。用户正常退出旧版后，已将扫描过的包内六个运行文件逐字节同步至 bin，EXE 文件版本为 1.2.0.0；未自动启动真实监测。

目前仅有单显示器 150% 的实际 DPI 验证。100%、125%、200% 以及不同缩放显示器之间的真实视觉效果尚未实测，不将程序化布局检查等同于这些环境的验证。桌面 computer-use 工具拒绝访问测试窗口（Computer Use was not approved to use tests），因此未完成三个真实托盘菜单的人工式视觉并排比较；原生控件交互测试与 DPI 查询已通过。用户可在交互预览或更新后检查菜单清晰度、Esc 和点击外部关闭行为。

## 仍需用户在真实登录周期检查

任务管理器中的启用/禁用和下一次真实登录启动行为，需要在用户愿意注销或重新登录时完成；自动测试不会注销或重启电脑。快捷方式目标、参数与工作目录可直接检查，不能替代登录验收。

自动化未捕获显示事件是无闪现的程序级证据；不同 Windows 更新、终端设置和显示环境下仍建议进行人工观察。
